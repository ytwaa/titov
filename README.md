# Учёт личных трат

Учебный проект: веб-приложение для учёта личных расходов студента. Серверный рендеринг на Go, без внешних веб-фреймворков.

## Стек

- Go, стандартный `net/http`
- `html/template` — серверный рендеринг HTML
- Хранение данных в памяти (срез), без БД (до этапа 3)

## Структура проекта

- `main.go` — точка входа: маршрутизация и запуск сервера
- `internal/handlers` — HTTP-обработчики и хранилище трат (срез в памяти)
- `internal/models` — структуры данных (`Expense`)
- `web/templates` — HTML-шаблоны (layout, список трат, форма добавления)
- `web/static` — CSS

## Запуск

Из корня проекта: `go run .`

Сервер стартует на `http://localhost:8080`.

## Маршруты

- `GET /` — список трат (сортировка по дате, новые сверху)
- `GET /add` — форма добавления траты
- `POST /add` — добавление траты, после успешной записи redirect на `/` (паттерн Post/Redirect/Get)
- `GET /about` — текстовое описание проекта
- `GET /ping` — возвращает `pong`; при любом другом методе — 405 Method Not Allowed

## Статус по этапам задания

- ☑ Этап 1 — HTTP-сервер на `net/http`, маршруты `/`, `/about`, `/ping`, обработка методов, 405 на `/ping` при не-GET.
- ☑ Этап 2 — структура по слоям, `html/template` с общим layout, модель `Expense`, список трат и форма добавления (хранение в срезе, без БД), redirect после POST.
- ☐ Этап 3 — SQLite и репозиторий
- ☐ Этап 4 — категории и фильтрация
- ☐ Этап 5 — регистрация и авторизация
- ☐ Этап 6 — статистика
- ☐ Этап 7 — валидация и обработка ошибок
- ☐ Этап 8 — экспорт в CSV, `.env`

## Известные ограничения текущей версии

- Данные о тратах хранятся в памяти (срез) и сбрасываются при перезапуске сервера
- Парсинг шаблонов выполняется на каждый запрос (не кэшируется) — упрощает отладку, но медленнее
- Доступ к срезу защищён `sync.Mutex`, т.к. `net/http` обрабатывает запросы конкурентно
